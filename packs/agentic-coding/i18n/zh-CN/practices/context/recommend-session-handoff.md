# 当历史上下文价值降低时建议换新对话

## 适用场景

大部分历史对当前工作或用户计划的下一阶段已没有多少价值时，即使尚未出错，也可使用；旧方向已经干扰有效决策时同样适用。简洁交接能保留必要上下文时，可以留下已完成的调查、日志和被替代方案。如果会话边界已确定，只剩记录哪些内容的问题，应编写检查点。

## 具体指导

1. 明确接续目标：剩余工作及已约定的下一阶段。选出约束其输入、承诺行为、数据处理、条件结果及拟开展或复用证据的事实和条款，保留限定与决策状态，不逐个主题概述。留下无关或被替代的历史，纠正已知偏移；下个重点未定时保留问题。
2. 简短记录能够替代大量无关历史或消除干扰时，建议迁移。不必等到出错，也不使用轮数阈值。历史仍有用且未造成干扰，或工作即将结束且没有接续任务时，继续工作。
3. 写概述前，逐条把选中的原文条款映射到交接中的位置：简短文字直接保留，或指定某步行动前要读取的精确位置。起草用的映射表不放入交接。保留独立义务和条件分支，不只覆盖主题；数据处理和凭据存储限制不能统称“隐私”后省略。保留最小完整条款及其条件、例外、结果与决策状态；转述可能改变边界时才引用，不搬整组规则。区分已接受要求、提案和假设，“继续讨论”不等于接受。保留实验证据时，同样映射方法控制，不只记结果和局限。后续流程可留在可访问来源的精确位置，但该处必须保留相关规则及状态；文档名或整段历史链接不行。没有可用引用时纳入必要条款，而非周围讨论。删去敏感值。
4. 写一份紧凑的行动记录：目标、当前状态、决策、证据边界、下一步及必要来源指针。短约束直接写入主文；只有无法引用现有产物的必要细节才另设按需区，不为每个主题再写一层概述。每项事实只出现一次，开场引用记录即可。当前事实未知就说明未知，不重述过时快照。相邻任务只留依赖，不展开方案或列“省略了什么”；被否决选项只留仍约束选择的理由。删去不改变下一步决策的旧数字、目录清单和排错经过。
5. 按来源保留历史路径。只有来源或明确检查确定了该项目根目录时，才使用绝对路径；当前工作目录本身不是依据。根目录未知时保留相对路径并注明缺口，不猜补。本轮新建交接的实际位置是有效的新信息，应与历史产物位置区分；省略无关环境或测试框架细节。
6. 将起草映射中的每条原文与保留文字或精确的必读位置逐一对照，核对输入包含/排除范围、独立义务、条件、例外、结果、方法控制和原有决策状态。主题标签、“保留契约”或可选的泛化来源索引不能代替漏掉的规则。删除不改变接续决策、必需行为或可用起始行动的内容，不为缩短文件而删掉起约束作用的事实。在稳定边界说明迁移收益，提供交接及可直接粘贴的开场指令。

当用户能够依据记录接续时停止。用户留在当前会话时继续工作；只有发生实质变化才再次建议迁移。

## 反模式

漫长的网关设计讨论结束后，实现只需已接受行为、约束和相关文件。Agent 等到出错才建议重开；随后又在背景、状态和完整开场 prompt 中重复同一设计，把被否决方案列为待选，并用当前目录补全历史相对路径。新会话继承了更多阅读负担和没有依据的项目位置。

## 原因

历史在明显偏移之前就可能增加阅读成本，并与当前指令竞争。交接只有在保留有效依据、避免重建全部历史或用编写者的环境填补缺口时，才能起到作用。

## 例外与边界

依据相关性判断迁移，长度或连贯性本身都不够。如果准备和加载交接增加的工作更多，就继续当前会话；一个阶段完成后仍可以交接下一阶段。独立粘贴的 prompt 需要足够上下文或可用的共用引用。先删除重复，再考虑删减必要约束；固定字数上限不能证明信息足够。文本变短本身不能证明总成本降低或后续执行更好。

## 示例

用户完成网关设计后要求实现。大部分历史是 tokenizer 实验和被否决的文本类型白名单，尚未发生错误。Agent 记录已接受的字节估算、预扣和完成后多退少补，以及排除已知文件载荷、保留其他内容的行为；只说明一次实现尚未验证，并保留白名单会低估的否决理由。历史路径 src/estimate.ts 的项目根目录未知，就保持相对。Agent 保存交接、提供实际位置，再给出读取交接后开始实现的简短开场指令，不再复述全部讨论。
