# 保持验收路径可完成

## 适用场景

提交一个会在任务自身交付路径上加检查、或从其输出中剥离信息的计划之前适用；实现过程中即将中途做这两类事时再次适用。完整性走查覆盖每条验收条件（含错误、重复和重开场景）；摩擦走查只走主路径。小到无需计划的任务，退化为"具体指导"末尾的一个问题。

## 具体指导

把每条验收条件写成从发起动作到可观察结果的有序步骤，包含变更加入的每个检查。先走所有条件查完整性：没有 owner 的必需步骤是映射缺口，先补再谈轻重。再走主路径查摩擦：每个能拒绝、拖延或要求干预的新增检查都是闸门。给每道闸仍能拦住可指名失败的最低档——observe（记日志）、mark（在结果上标注）、confirm（问一次，且在触发处有人能回答）、block（拒绝）。高于 observe 的档位只能由本部署事实或契约中存在的演员和路径支撑；风险类目名或泛化的攻击者什么都支撑不了。宁把有理由的闸门收窄到高风险子集，不闸整条路径。做删除测试：说出删掉它具体会坏什么、坏给谁；答不出就删闸。信息隐藏是同一场测试里的另一种保护：在一个面上藏起一个事实，只有指名谁会在那里看到它而受害才成立。凭据值、认证头、私有 query 串指得出这种受害；在请求用户已经控制的面上——本地 CLI 自己的诊断输出——真实路径、权限状态、日志内容和失败原因指不出任何受害者，藏掉它们只是拿走这个面本来要传达的事实。把隐藏收窄到承载指名伤害的字段；当材料要离开这台机器——导出打包、外发反馈——在那个边界做脱敏，而不是降级本地面。没人能回答的 confirm 就是 block——降档或收窄并给文档化旁路。然后走一次失败：挑最可能失败的那条检查，让它单独失败，说出还有什么活下来；如果单条失败会作废其他所有已满足的条件，要指名谁需要这种严格度、归因式或部分结果会怎样误导。把档位和指名失败记在闸门的计划条目旁。当每条验收条件都能在验收或政策未提名的干预之外完成、且每道闸都指名了其档位拦住的失败时停止。小到无需计划的任务只问：我加的检查是否挡住了验收路径？是就降档或收窄。

## 反模式

任务给本地 CLI 加一个 config-set 命令。Agent 连同键 allowlist、路径穿越校验、属主权限检查和每次写入确认一起交付。验收场景——开发者跑命令、配置更新——从此需要请求从未提过的交互和授权，而且调用该 CLI 的脚本无法回答确认。校准在交付之后才到，形式是删代码。姊妹变更给同一个 CLI 加诊断命令，计划要求 text 和 JSON 输出一律不得暴露真实路径、权限位或日志内容，理由是安全。验收场景里没有任何东西被它服务：调试自己机器的用户失去了事实，而这条要求拦不住任何攻击者够得着的东西。校准在这里也是交付之后才到，形式是恢复输出。

## 原因

逐条审查只看见每道保护的故事，看不见组合后的路径；训练对可见事故的定价高于不可见的不可用性，所以未经走查的计划理性地过度保护——而一个事实被从它自己的面上藏掉，是不可见不可用性最纯粹的形态。Practice 只改善它指名的维度：完整性、摩擦和失败组合必须各走一遍才各自改善。

## 例外与边界

治理政策或合规可以在没有本地可达性的情况下强制档位或强制脱敏——注明政策，保留。真实可达的威胁配得上 block；本条做校准，不移除正当防护。既有系统防护是约束，不是删除测试对象；若它们使验收不可能，上浮冲突而不是移除。检查归属哪层、是否重复，是边界归属问题。

## 示例

config-set 走查把四道检查全开的主路径写下：命令、allowlist、权限、确认、写入、验证。删除测试：穿越输入到不了路径、操作系统已强制文件属主、确认拦截的是验收没提的笔误——全部降级或删除。一个关切带证据存活：覆盖 security-token 键会迫使别处重新认证。闸门收窄为仅该键子集的一次确认；其余键无打扰写入，变更记入日志。批量导入走的是失败一侧：它"一坏全坏"的整批拒绝规则被收窄为归因那一条无效行并报告其余结果，而不是作废每一条已满足的行。同一份计划里 doctor 输出带着一条草稿要求：隐藏真实路径和权限位；删除测试发现这个本地终端前没有会被路径伤害的观众，于是收窄为只遮蔽输出中的 token 值，外加输出被打包外发反馈时的一个脱敏步骤，本地诊断保留全部事实。
