## 何时应用

当实现或修改列表或搜索响应，而其集合可能超出一个较小、已确立的上限时应用。确定每次请求获取多少数据，以及调用方如何继续遍历结果。

## 指导

1. 阅读现有导航契约，了解预期集合规模。设置默认分页大小和强制执行的最大值，并明确处理缺失、无效和过大的分页大小。省略上限不能意味着无限制获取。
2. 在获取阶段、完全物化或序列化之前应用上限。对所包含且可独立增长的子集合也设置上限；父集合分页不能限制无限增长的子集合。在整个遍历过程中保留相同的访问范围和筛选条件。
3. 定义确定性排序，并使用唯一键打破排序并列。说明请求之间发生新增、删除或重新排序对调用方意味着什么。仅有稳定排序并不能提供快照。
4. 让后续遍历方式符合导航需求。对于小型或稳定列表，以及直接跳页，偏移量或页码分页是合理的。在排序键支持时，基于键集的游标可以适合深度顺序遍历。将偏移量编码为游标，并不能消除偏移成本，也不能消除并发写入下的位置移动。
5. 返回既有的下一页链接、游标或分页元数据，让调用方能够区分遍历完成与结果截断。让后续遍历与排序及筛选条件一致。在有界范围内多获取一行即可判断是否还有下一页；仅在确有要求且成本可接受时包含精确总数。

当获取操作强制执行默认值和最大值，排序及并发变更行为已明确，所包含的集合均有界，并且无需获取所有行就能通过后续遍历信息识别终点时，即可停止。

## 反模式

`GET /events?limit=50` 加载所有匹配的事件，对数组排序，然后切出 50 行。其响应看起来有界，但内存占用和传输的查询结果仍会随完整历史数据增长。

## 原因

响应切片无法撤销已经发生的无界获取。获取上限约束物化规模；排序和后续遍历方式则让遍历可预测，但并不意味着数据集保持不变。

## 例外与边界

真正很小的固定集合可以整体返回。应保留已认可的流式或异步导出契约，而不是悄然截断它们。行数上限并不限制行宽、排序工作量、昂贵的筛选或查询总成本。无论偏移量分页还是游标分页，单独使用都不能保证快照。

## 示例

事件流默认返回 50 行，最多允许 200 行，并按 `occurred_at DESC, id DESC` 排序。基于键集的后续遍历信息携带这两个值，并保留租户筛选条件。一个 50 行的分页最多获取 51 行，仅在额外一行存在时输出下一页游标。之后插入在游标之前的数据会在刷新时出现，而不是出现在某个承诺不变的快照中。
