## 何时应用

当端点通过对象 ID 或租户选择要读取、下载或更新的对象时应用。身份认证即便正确，调用者仍可能访问到其他用户的记录。匿名的公开或共享请求同样遵循目标资源的可见性策略；不要要求所有地方都必须登录。

## 指导

1. 明确主体、操作、目标，以及适用时的租户。需要身份时使用经过验证的身份；否则显式表示匿名调用者。从权威状态中解析成员关系、授权、可见性和资源属性，而不是采信提交的所有权声明。
2. 应用实际的允许规则，拒绝不匹配的情况。规则可以允许公开读取、共享、所有权操作、委托操作或显式的跨租户访问。“已登录”和“仅限所有者”都不能代替该策略。通过既有机制验证任何共享访问凭证。
3. 将数据选择与该授权决定绑定。按允许的可见性和租户限定集合范围；在释放受保护字段或改变状态前，使用限定范围的查找，或仅加载策略所需的输入。随机 ID 和 URL 中的租户 ID 都不等于权限。
4. 覆盖替代路径以及批量操作影响的每个目标。通过既有的条件写入、事务或强制执行的数据策略，保持依赖状态的权限判断与变更一致。之前浏览过页面并不意味着后来就有权执行变更。拒绝请求时不得泄露受保护数据。

当预期策略已在每条受支持路径上控制数据和副作用，包括合法的公开或共享访问时，即可停止。复用既有的授权机制。

## 反模式

处理器检查会话后，直接按主键更新文档，未检查租户或编辑权限。修改 ID 就会更新另一个租户的文档。即使加上“仅限所有者”的条件，仍会错误地拒绝显式授予的共享编辑权限。

## 原因

有效调用者也可能无权执行特定操作，而匿名调用者也可能有权读取公开内容。将操作与权威的目标资源策略关联起来，可以防止通过替换标识符越权，同时不破坏有意提供的共享能力。

## 例外与边界

单租户系统不需要人为引入租户抽象。全局角色只有在策略明确规定时才授予跨租户访问权限。如果应用上下文无法绕过强制执行的数据库策略，可以由这些策略负责执行授权。私有辅助函数可以复用仍然有效的授权决定，无须重复判断；入口处的身份认证仍是独立事项。

## 示例

某发票端点仅允许匿名下载已发布的公开发票。下载私有发票需要具备该发票所属租户的成员资格和账单读取授权。猜中的 ID 绝不会扩大其查询范围。获得显式授权的会计可以读取共享发票，而不必拥有该发票；仅有有效会话不能暴露其他客户的账单。
