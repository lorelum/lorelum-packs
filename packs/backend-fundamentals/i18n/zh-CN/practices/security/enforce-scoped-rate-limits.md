## 何时应用

当操作的滥用风险或资源成本要求限制请求准入时应用，例如登录尝试或昂贵的报表生成。定义该操作的策略，而不是到处套用同一个示例配额。

## 指导

1. 明确操作、预算归属方、计入的尝试、突发额度或时间窗口，以及恢复准入规则。已认证主体的键应从经过验证的身份派生，而不是来自提交的 ID 或原始秘密。将不相关操作的预算分开。
2. 对于登录攻击预算，未经验证但经过规范化的目标账户标识符可以用作键，但它不是身份证明，也不是可信主体。使用有界策略，防止攻击者导致受害者账户被锁定。对于网络键，使用配置好的代理信任和受支持的地址处理方式；任意转发请求头都不具有权威性。考虑共享 NAT 的情况。
3. 让计数器存储与承诺的作用域相匹配。内存是进程本地的，并且可能在重启时重置。跨工作进程共享的配额需要现有网关，或支持原子计数、过期和独立命名空间的受支持共享存储。独立计数器无法承诺严格的全局额度。
4. 在受保护的昂贵工作之前进行准入判断，同时保留用于建立可信键所需的身份认证。使用受维护限流器提供的并发安全机制。依据服务策略，明确定义存储故障时的失败行为或有界回退行为：故障不等于配额耗尽，不得意外变成无限制回退，也不得声称配额仍在执行。
5. 在产生效果之前拒绝真正超出预算的请求，使用服务的错误格式和 HTTP 429，并在已知时提供真实的重试时间。区分准入基础设施不可用与配额超限，不要将基础设施故障报告为 429。

当操作具备有界策略，且其键、计数方式、部署作用域、拒绝位置和故障行为均符合合法流量契约时，即可停止。

## 反模式

部署了多个副本的服务使用进程本地的按 IP 计数器，却把每个请求都识别为来自负载均衡器，随后又通过信任原始 `X-Forwarded-For` 来修正。客户彼此阻断，而攻击者则选择全新的计数器。

## 原因

操作、键、时间边界和共享状态共同定义了限制。可伪造的键允许绕过；范围过宽的键会造成附带拒绝。存储故障无法证明调用方已经消耗了预算。

## 例外与边界

当重置行为和作用域可以接受时，尽力而为的单进程内存限制是有效的。当所有相关入口流量都经过网关时，无需重复执行网关已有的限制。请求速率不能限制并发数、请求大小、查询成本或账单，也不是抵御拒绝服务攻击的保证。

## 示例

登录流程针对规范化后的提交账户名设置尝试预算，并将其与基于可信代理来源的预算分开。该账户键不赋予任何身份。其有界节流策略避免永久锁定受害者账户，而计数器存储故障遵循配置好的服务不可用策略，而不是虚构配额耗尽。
