## 何时应用

实现 URL 预览、远程导入、回调或其他目标地址可受外部影响的服务端发起抓取时应用。确定该操作可以联系哪些目标，包括间接重定向和解析出的地址。对提交请求的调用者完成身份认证，并不等于获得了访问该目标地址的权限。

## 指导

1. 声明集成约定：允许的协议方案、主机、有效端口和地址范围。对于已知集成，优先使用服务端控制的目标配置或显式允许列表。如果需要任意公共目标，显式定义公共网络访问范围，并使用持续维护的 IPv4/IPv6 地址分类，排除元数据地址、环回地址、私有地址、链路本地地址和其他不允许的范围。窄范围地允许合法的内部集成，而不是放开所有内部网络。
2. 使用与实际 HTTP 客户端兼容且持续维护的 URL 和地址库进行解析。比较规范化的协议方案、完整主机名、有效端口和规范 IP 值；不要使用子串或前缀匹配。拒绝不支持的协议方案、存在歧义的解析器解释和不需要的 userinfo。根据可信配置重建固定集成的 URL，而不是转发不必要的提交组件。
3. 解析名称，并对所有返回的 IPv4 和 IPv6 候选地址应用地址策略。将连接绑定到经过验证的地址，不再进行第二次未经检查的解析，同时保留预期主机名供 HTTP 和 TLS 证书验证使用。每次连接尝试，包括既有重试或回退路径，都必须遵循该策略。当解析或执行控制无法确认目标被允许时，拒绝请求。
4. 除非确有需要，否则禁用自动重定向。跟随重定向时，相对于当前 URL 解析其目标，并在连接前重新完成协议方案、主机、端口和地址的完整判断；限制重定向链长度。通过既有网络或代理控制实施相应的出站限制，包括代理实际的解析和连接路径。先在应用侧查询地址，随后让代理不受约束地抓取，并不能实现绑定。

当每个可能的出站连接都被限制在该操作允许的目标范围内，包括重定向和 DNS 变化的情况时，即可停止。仅解析 URL 并不提供这种保证。

## 反模式

预览处理器检查字符串是否以 `https://` 开头，解析一次主机名，然后允许客户端再次解析并跟随重定向。公共地址通过了检查；实际连接却到达了本地管理服务。

## 原因

后端可以访问提交请求的调用者无法访问的服务。重定向、其他地址表示形式和变化的 DNS 应答，都可能使连接离开表面上可接受的 URL。连接时实施控制，才能保护实际联系的目标。

## 例外与边界

内部抓取可以是在特定集成策略下有意允许的行为。CORS 和入站身份认证不能限制服务端出站流量。目标地址控制并不能确保响应内容安全、远程授权有效，也不能意味着抓取可以不受资源预算限制。

## 示例

某文档导入器接受端口 443 上的公共 HTTPS 地址。其客户端只连接到获准的已解析地址，并重新检查每次被允许的重定向。另一个薪资集成允许访问一个配置好的内部服务；该例外不适用于文档导入。
