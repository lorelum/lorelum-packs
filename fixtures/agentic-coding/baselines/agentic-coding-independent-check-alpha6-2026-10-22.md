## Reading before deciding: controlled routing smoke

Two fresh answering sessions received the same session-start catalog metadata and four design-only cases: a first free-space threshold on read-only startup; redundant traversal/hashing on local HTTP status; repair blocked by inference readiness; and required public JSON, tenant, concurrent-publication, and release-verification protections. No Practice body was injected into either prompt. Each session chose its own knowledge actions.

| Observation | Catalog metadata only | Explicit project-style route |
|---|---:|---:|
| Sessions | 1 | 1 |
| Actual keyword queries | 1 | 0 |
| Successful full-body gets | 1 | 3 |
| Decisions after the new body was fully read | 4/4 | 4/4 |

Catalog-only queried once, selected the independent entry first, fetched its body, and reused it for the later three cases. Its full-body read was event 8; the first design decision was event 9. The explicit arm got the independent, ownership, and acceptance-path bodies directly, without relying on ranking; its new-body read was event 3, before the first design decision at event 11. Complete CLI results and per-case decisions are retained in JSON; ephemeral trace IDs and artifact URLs are omitted where represented separately.

Both sessions declined the unsupported startup threshold, omitted the duplicate HTTP traversal/per-poll hash while retaining actual transport guarantees, kept independently authorized repair usable without inference readiness, and required external-input, resource authorization, atomic publication, signature, and integrity protections. These observations show pre-decision body acquisition and appropriate stated choices in these cases. They do **not** establish that the Practice changed a decision: neither arm was a no-knowledge blind control, and both made the same four choices. The route did not demonstrate an advantage over catalog-only in this one round.

The explicit route was manually supplied to the controlled session. No product AGENTS.md, required skill, or host Plugin was modified or exercised. Four decisions sharing one read in one session are not four independent trigger trials. No product code was implemented or run by these design sessions.

## Limits

Semantic quality was not evaluated this round. The same alpha.6 Windows model-load prerequisite already failed with `embedding.deadline-exceeded` in the [preceding evaluation](./agentic-coding-backend-checks-alpha6-2026-10-22.md), including an explicit evaluation request budget; no model/runtime change was made, and that failure was not rerun just to confirm it. There are no candidate single-vector or multi-view ranking results.

The independent entry has a distinct retrieval job and limited positive evidence, including two correctly selected near-neighbors and a successful catalog-driven pre-decision read. This is stronger than merely adding fixtures or emphasizing an unread body. It still does not establish stable automatic triggering, semantic improvement, causal decision improvement, or production safety. Repeated unseen tasks and actual host routing remain untested; the new entry is not published or installed into the user's Store.
