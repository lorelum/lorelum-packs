# Handoff 轻量对照方案

比较我们的 Practice 与 Matt Pocock handoff skill 生成的交接内容：依据完整对话，判断哪份对接续任务更完整、更合理，有无遗漏或混入不该携带的信息。本轮只评交接质量，不执行新对话后续任务，也不把“是否主动建议迁移”纳入两组胜负标准。本目录为 evaluation_only，不是运行时输入。

## 输入与生成

先选 3–5 段约 15 轮以上的真实对话，提取交接切点前每轮用户和 Agent 输出，保留轮次编号和角色。1 轮按一次用户输入及对应 Agent 回复计；15 轮是样本筛选条件，不是 Practice 触发阈值。

样本尽量覆盖：大量历史已无关但尚未发生错误；目标变化、方案否决或约束修正；当前阶段完成、准备进入下一阶段。根据用户已表达的意图注明接续目标，同样提供给两组。接续目标应让模型自行依据原文识别有效决策，不能直接提示哪种旧方案要删或把预期答案写进去。

- A：用户提供的 Matt Pocock handoff skill（见下方来源）。
- B：packs/agentic-coding/practices/context/recommend-session-handoff.md。

A 来源：https://github.com/mattpocock/skills/blob/main/skills/productivity/handoff/SKILL.md

保存实际使用的两份指导正文。相同模型、参数、对话、接续目标和输出预算，每组每样本先生成一份 handoff，只替换指导正文。公共请求直接要求生成交接，不要求两组判断是否迁移：

> 请按提供的指导，基于以下完整对话，为给定接续目标生成供新会话使用的 handoff。不要执行后续任务。

若输出为文件，取文件正文作为交接。给评审提供本轮新建交接的位置等必要执行事实，不暴露指导名称；新建文件不必事先出现在历史中。历史项目路径仍须有来源，不能用测试目录补全。实验输入去除敏感值；不要求额外导出全部工具调用或补齐外部文件。引用材料如果现成可得，可同样提供给两组；材料缺失时评审注明核实范围，不让补齐材料成为第一轮前置条件。

## AI 依据原文比较

不必预先制作人工核对表。让 AI 读取完整对话、接续目标和两份匿名交接，一次完成原文核查和比较；随机排列两份交接，隐藏指导名称。评审重点：

| 问题 | 判断依据 |
| --- | --- |
| 必要信息有无遗漏或歪曲？ | 接续任务需要的目标、约束、背景、决策、进展和待决问题是否准确保留；不只看紧接着的一步 |
| 有无决策状态混淆？ | 被否决或替代的内容有无变成当前方案，假设或 Agent 提议有无变成用户要求 |
| 有无不当携带或新增？ | 无关探索和日志是否混入，有无凭空新增要求、权限、完成或验证结论 |
| 哪份更完整、更合理？ | 在保留必要信息的前提下，哪份更清楚地支持接续目标，并留下更少无用历史 |

被否决方案如果明确标注且其理由仍影响接续工作，不算污染。较早的信息只要仍有效就应保留。完整不等于复制全部历史，简短也不能弥补关键遗漏。

可直接使用的评审请求：

> 请根据完整对话和接续目标，分别核查两份匿名 handoff，再比较哪份更完整、更合理。列出各自的必要信息遗漏或歪曲、决策状态混淆、无关内容和无依据新增。每项问题引用原始轮次与交接原句；遗漏时说明缺少的事实及来源。区分“原文支持”“原文冲突”“材料不足”。已否决内容若明确标注且有助于接续，不算污染。不要仅凭篇幅或文风判断。最后给出更合适的一份、持平或各有取舍，并解释依据。

只在评审有争议、来源不明或结论与引用不符时人工回看。不要求所有样本经过人工核对才能得出第一轮观察。

## 记录与结论

保存原始对话、接续目标、两份指导与输出、模型和参数、匿名顺序及评审结果即可，可先放在 tmp/handoff-eval/。逐样本记录错误、遗漏和比较结论，不要求统一总分或先过一套合格门槛。两组相当就记为相当；篇幅可作辅助观察。

每次运行保存指导快照；看过样本后修订再跑，标为探索性迭代，不把旧结果转给新正文。结果只说明这些样本上的交接内容质量；同模型控制能减少生成条件差异，原文引用便于核查评审，但不能消除模型能力影响，也不证明自主触发、总成本下降或后续执行改善。第一轮完成后再根据实际差异决定是否修改 Practice 或补充样本。
